# 再生主体の切替

[#61](https://github.com/4rtofl/Audipp/issues/61) は FR-PLY-03/07、FR-NET-03、DD-QUEUE-04、TEST-QUEUE-01 のうち、再生主体の停止確認、取消、遅延応答を扱う。

- `PlaybackOwnerCoordinator` は再生側の単一ルーパー上で、現在の主体、遷移ID、キューと項目ID、revision、次の要求を管理する。アダプターは開始・停止の結果を同じルーパーへ通知する。開始や停止のコマンド受理は観測結果と区別する。
- 停止要求後に対応する非再生状態を観測し、先に送った開始要求も終端したら次へ進む。新しい開始の直前に `SourceResolver` の許諾・経路・遷移の検査とキューrevisionの照合を行う。開始後は再生を観測して初めて `ACTIVE` にする。
- Stop・別曲・項目削除・経路変更の際は保留中の開始を破棄する。取消後に古い開始の成功が届いたら、別の照合トークンで停止を再要求する。旧開始の応答が未確定の間は次の開始を保留する。同じSDKで古い再生を止める操作が、新しい要求まで止めることを防ぐためである。
- 確認の期限はCoordinatorのスコープで管理する。停止が確認できなければ `STOP_UNCONFIRMED` を返す。旧開始が終端済みなら、利用者の手動停止と継続確認を受け付ける。その場合も、停止を観測できなかった遷移IDを状態に保持する。
- 外部アプリへの引き渡しは利用者の明示操作を待ち、再検査してから開く。引き渡し後の再生状態は `ACTIVE` に更新しない。

`PlaybackOwnerCoordinatorTest` の9件で、ローカル・Provider・ネットワーク間の切替、停止観測の待機、キューや経路と許諾の再検査、停止確認待ちの取消、遅延成功、期限切れ、手動継続、外部アプリ引き渡しを確認した。実Serviceからアダプターへの効果の接続と連続再生は [#83](https://github.com/4rtofl/Audipp/issues/83) の範囲。実機と実サービスの動作確認は未実施。
