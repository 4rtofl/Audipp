# 再生予定の計算

[#63](https://github.com/4rtoflow/Audipp/issues/63) は FR-PLY-06/09、DD-QUEUE-03、TEST-SCHEDULE-01 を扱う。

- `calculatePlaybackSchedule` は再生側から、同じ時点の `PlaybackSnapshot`、実際の項目順、速度、リピート設定、現在時刻を受け取る。曲長は項目が指定する Variant ID で取得する。シーク、並べ替え、曲長・速度・経路の変更時は、新しい入力で再計算する。
- 算出に使う速度の範囲は0.25〜4.0倍（両端を含む）。範囲外の速度は未知として扱う。
- 再生中は、既知の残時間だけで到達できる範囲の開始予定を返す。全項目の残時間が確定している場合に終了予定も返す。未知区間の先に既知の曲長があれば、その曲の残時間は保持する。
- 一時停止とバッファリング中は残時間だけを返す。リピート中は現在曲の残時間と繰返し状態だけを返す。外部経路で位置の取得能力がない場合は現在位置を未知とし、再生順・速度が不明な場合や外部アプリへの引き渡し時は算出不可を返す。信頼できない曲長は入力から外す。

ローカル再生では、再生エンジンから位置・曲長・速度を取得した時点の時計時刻で、選択した1曲の予定を更新する。再生サービスは再生状態と予定をアプリ内コントローラへ公開する。シーク要求時に位置と予定を未知に戻し、シークに伴う位置の変化を観測してから再計算する。

台帳に `PlaybackScheduleTest` の計算・ローカル再生のケースを記録する。実機での表示や外部サービスのタイミング計測は未実施。

シャッフル済みの実再生順の決定は [#60](https://github.com/4rtoflow/Audipp/issues/60)、キューと再生サービスの接続は [#83](https://github.com/4rtoflow/Audipp/issues/83) で行う。再生主体の切替は [#61](https://github.com/4rtoflow/Audipp/issues/61)、画面からの表示は [#86](https://github.com/4rtoflow/Audipp/issues/86) が担当する。
