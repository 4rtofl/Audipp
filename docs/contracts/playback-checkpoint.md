# 再生チェックポイントの保存と復元

[#62](https://github.com/4rtofl/Audipp/issues/62) は FR-PLY-04、NFR-REL-03、DD-PLY-03、DD-DB-02 と TEST-RESTORE-01 の保存・復元を扱う。

- `PlaybackCheckpointJournal` は、キュー・項目の変更、シーク、一時停止、停止が確定した時点のスナップショットを `saveConfirmed` で受け取る。再生中に位置を観測できる場合は、サービス側のスコープで5秒ごとに位置を取得する。
- 保存はIOコルーチンひとつで直列化する。保存が遅れている間は待ち行列に最新の位置だけを残し、再生側を待たせない。キューのrevisionが古い書き込みはRoomで拒否し、DBエラーでは直前のコミットを保持する。
- `restorePlaybackCheckpoint` は保存済みのキュー・現在項目・選択版をひとつのRoomトランザクションで読み、`SourceResolver` で現時点の音源・権限・経路を再検査する。消失や失効時はキューだけを返す。保存位置と選択版の曲長が揃えば曲長を上限とし、未知の位置はそのまま返す。復元処理から再生命令は送らない。

Robolectric API 35 のホスト試験7件で、終了時の追加保存を行わずにDBを再オープンし、最後にコミットした項目と位置を復元した。5,000 msのタイマー契約と、5,000 msで保存した後に7,000 msで停止するシナリオで2,000 ms戻ることを確認した。ホストの1試行では、テストがタイマーを進めてから保存結果を観測するまで11 msだった。

実Serviceへのイベント接続、端末でのプロセス強制終了、実機での保存遅延は [#83](https://github.com/4rtofl/Audipp/issues/83) で検証する。
