# 再生チェックポイントの保存と復元

[#62](https://github.com/4rtofl/Audipp/issues/62) は FR-PLY-04、NFR-REL-03、DD-PLY-03、DD-DB-02 と TEST-RESTORE-01 の保存・復元を扱う。

- `PlaybackCheckpointJournal` は、キュー・項目の変更、シーク、一時停止、明示停止の確定後に `saveConfirmed` でサンプルを受け取る。明示停止には停止直前に取得した項目と観測位置を渡す。項目の切り替えに伴う一時的な `IDLE` は確定イベントの対象外とする。項目のないサンプルを保存するとき、同じキューの既存の再開点はDAOが保持する。現在項目の削除・全消去ではDAOが再開点をクリアする。再生中に位置を観測できる場合は、サービス側のスコープで5秒ごとに位置を取得する。
- 明示停止後も同じ停止状態とキューが続き、停止直前の項目がキューに残っている間は、呼び出し側で停止直前のサンプルを保持する。リピート変更などでそのキューの revision が進んだら、停止直前のサンプルにコミット済みの最新 revision を設定して `saveConfirmed` に渡す。停止時の保存結果を待たず、キュー変更の確定時に行う。項目なしの `IDLE` を渡すと、待機中の停止サンプルが置き換わり得る。キューの切替、対象項目の削除・全消去、停止状態の終了時は保持したサンプルを破棄する。
- 保存はIOコルーチンひとつで直列化する。保存が遅れている間は待ち行列に最新のサンプルだけを残し、再生側を待たせない。`currentPlayback` と `saveConfirmed` にはコミット済みの最新キューrevisionを渡す。`lastWrite` が `STALE_QUEUE` を報告したら、一時停止中も呼び出し側で最新キューと再生状態を読み直し、最新revisionに対応するサンプルを送り直す。明示停止の再送には、最新のキューと停止状態に対応することを確認できた停止直前のサンプルを使う。DBエラーでは直前のコミットを保持する。
- `restorePlaybackCheckpoint` は保存済みのキュー・現在項目・選択版をひとつのRoomトランザクションで読み、`SourceResolver` で現時点の音源・権限・経路を再検査する。`STALE_ROUTE` と `STALE_TRANSITION` は最新の文脈で一度だけ再解決する。`SOURCE_MISSING`、`PLAYBACK_UNSUPPORTED`、`POLICY_BLOCKED`、`INVALID_DESCRIPTOR` では理由付きでキューのみ返す。`AUTH_REQUIRED`、`PERMISSION_REQUIRED`、`EXPIRED`、`TIMEOUT`、`SOURCE_IO`、`TARGET_UNREACHABLE` を含むその他の失敗では項目・保存位置と最後の失敗理由を返し、再生要求時の再検査に委ねる。解決中にチェックポイントが変われば復元結果を破棄する。選択版の曲長が分かる位置は曲長を上限とし、曲長や位置が不明なら位置は `null` とする。外部引き渡し先または位置取得不可と解決できた場合も位置は `null` とする。復元処理から再生命令は送らない。

Robolectric API 35 のホスト試験では、5,000 msのタイマー間隔と、終了時の追加保存を行わずにDBを再オープンしたときに最後のコミットを復元することを確認する。従来の記録にある巻戻り2,000 msは、fixture上の位置7,000 msと保存位置5,000 msの差の例。11 msは、ホスト1試行でタイマーを進めてから保存結果を観測するまでの時間。

保存が継続して成功する場合の定期保存による最悪の巻戻り幅は、保存周期5秒、スナップショットの古さ（現行Serviceの更新周期は約1秒）、保存遅延の和。保存遅延により約6秒を超え得る。`STORAGE_ERROR` や `STALE_QUEUE` が続く間は上限がない。

実Serviceへのイベント接続後の受入条件として、終了コールバックなしのプロセス強制終了、API 23/36の端末試験、実機での保存遅延・I/O負荷時と保存失敗時の巻戻り幅、一時停止の確定保存が `STALE_QUEUE` になった場合の再送、停止直後のキュー変更で保存待ちの再開点を引き継げることを検証する。[#83](https://github.com/4rtofl/Audipp/issues/83) で Service につないだ。接続の内容と試験の範囲は[キューを使う連続再生](queue-session-v1.md)に記す。
