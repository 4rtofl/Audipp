# ライブラリ画面・登録進捗 v1（Issue #84）

対象は [Issue #84](https://github.com/4rtofl/Audipp/issues/84) の FR-UI-01 / FR-SRC-02 / FR-SRC-03 / FR-SRC-05 → DD-UI / DD-UI-02 → TEST-UI-01 / TEST-LIB-02 のうち、ページ付きの曲・アルバム・アーティスト・フォルダ・形式の一覧、ソートと絞込み、曲を選んで再生入口へ送る操作、登録進捗の画面です。画面 ID と戻り先は[ナビゲーション案 §3・§4](../specifications/12_navigation_proposal.md)、検索は #55 の `LibraryQueryDao`、アルバムは[アルバム分類](album-classification-v1.md)、アートは[アート](artwork-v1.md)、再生状態は [Now Playing](now-playing-v1.md) の契約を前提にします。以下の名前・寸法・並び・ページの大きさは実装提案で、採用済みの製品条件は変えていません。

## 画面

- Library タブ（LIBRARY）は1つの画面で、「曲・アルバム・アーティスト・フォルダ・形式」をラベル付きのフィルターとして切り替えます。選んだ表示・検索語・並び順は `NavigationViewModel` が持つので、回転やタブの往復で消えません。
- アルバム・アーティスト・フォルダ・形式の一覧で行を選ぶと、同じ画面がその項目の曲の一覧になります。「一覧に戻る」か戻る操作で項目の一覧に戻ります。アルバムを開くとディスク・曲番号の順に並べ、閉じると曲名順に戻します。
- 「音源を追加・管理」は登録進捗の画面（SOURCE）を開きます。ライブラリが空でも、読み込み中でも開けます。戻ると Library に戻ります。
- アルバムの結合・分割の画面は作っていません。Issue の範囲（一覧・ソート・絞込み・登録進捗）に含まれないためで、`LibraryAlbums` の API はそのまま使えます。

## 一覧の読み込み

| 一覧 | 問い合わせ | まとめ方 |
|---|---|---|
| 曲 | `observePages(LibraryQuery)` | 1行が1つの Variant |
| アルバム | `observeGroups(ALBUM)` | `album_id` ごと。同じ題名でも ID が違えば別の行。`album_id` のない曲は「アルバム未分類」の1行 |
| アーティスト | `observeGroups(ARTIST)` | 表示用のアーティスト名ごと（ASCII の大文字小文字を区別しない）。不明は「アーティスト不明」の1行 |
| フォルダ | `observeGroups(FOLDER)` | 走査ルートとフォルダの組ごと。表示はプロバイダーの文書 ID のまま。フォルダの記録がない曲は「フォルダ不明」の1行 |
| 形式 | `observeGroups(FORMAT)` | コンテナ（なければコーデック）ごと。不明は「形式不明」の1行 |

`LibraryQuery` には、アルバム ID（`albumId`）とフォルダ（`folder`）の絞込みと、ディスク・曲番号の並び（`TRACK_NUMBER`、番号不明は後ろ）を足しました。既存の引数は既定値のままで、#55 の呼び出しは変わりません。グループの検索語は項目の名前だけに当てます。

一覧は 100 行の窓で読みます。窓は最初に見えている行の 25 行手前から始め、25 行ごとに動かします。`LazyColumn` には全件の数だけ行を置き、窓の外の行は「読み込み中」の空の行にします。読み込む行は常に窓の 100 行だけなので、ライブラリの大きさに比例してメモリを使うことはありません。

表示・項目・検索語・並び順が変わると、前の問い合わせを取り消して「読み込み中」を出します。古い条件の行を新しい条件の下に出しません。スクロールで窓だけが動くときは、新しい窓が届くまで前の窓の行を残します（同じ条件の行なので、行の位置は正しいままです）。

問い合わせは Room の Flow で、主スレッドでは実行しません。アートは `ArtworkProvider.load` を行ごとに呼び、DB の読み取りは Room の suspend、画像の読み込みは `Dispatchers.IO` で行います。アートは曲とアルバムの行だけに出し、48 dp（64 px 以上の2の冪に切り上げた辺）で読みます。

欠損値は推測で埋めません。題名がなければ「曲名不明」、アーティストがなければ「アーティスト不明」と出します。長い題名は2行、アーティストは1行で切り詰め、TalkBack には全文が渡ります。

## 曲を選んでから再生まで

1. 行を選ぶと `LibrarySelection` が新しい `QueueEntryId`（`library-` と UUID）を作り、`LibraryDao.trackVariant` でその行の `TrackVariant` を読みます
2. `NavigationPlayback.play` が既存の `PlaybackConnection.playLocal` へ Variant を送ります。サービスと `PlaybackConnection` は変更していません
3. サービスが受け付けたら Now Playing を開きます（ナビゲーション案の「曲の再生受付」）。サービスがその entry を現在曲として報告したら選択の状態を消します

| 状態 | 条件 | ミニ・Now Playing の表示 |
|---|---|---|
| 送信中・受付済み | サービスがまだその entry を報告していない | 選んだ曲を「再生を準備中」として出す。曲名・アーティストはライブラリの値、アートは選んだ Variant。位置・曲長・形式・出力・操作は出さない |
| 報告済み | セッションの現在の entry が選んだもの | サービスの状態をそのまま出す |
| 失敗 | 曲がない、サービスに接続できない、拒否された、受付後に同じ entry で失敗した | 前の再生状態に戻し、一覧の上に曲名・理由・「再試行」を出す。別の曲も選べる |

前の曲の位置・形式・出力・アートを、選んだ曲のものとして出しません。新しく曲を選ぶと前の要求を取り消すので、遅れて届いた前の応答で状態は変わりません。別の entry の失敗は、選んだ曲の失敗として扱いません。このため `NavigationPlaybackState.Current` と `Failed` に、スナップショットの `currentEntryId` を足しました。

## 登録進捗（SOURCE）

- ホームと同じ登録の状態（件数、登録中、取消、権限の拒否・失効、読み込みのやり直し、フォルダの追加・選び直し）を先頭に出します
- 走査中は、確認した項目・読み終えたフォルダ・追加した曲・再確認した曲・音源として扱わなかったファイル・読めなかったファイルの件数を、`LibraryScan.progress` の値のまま更新します。全体の数は分からないので、割合は出しません
- 走査が終わったら、この画面から始めた最後の走査の結果（完了・一部だけ・取消・アクセス不可）、件数、見つからなくなった曲の数、理由（`LibraryScanIssue` をまとめた文言）を出します。結果はプロセスが終わると消えます
- 登録したフォルダごとに、文書 ID、最後の走査の状態、OS の読み取り許可があるかを出します。許可があれば「読み込みをやり直す」、なければ「フォルダを選び直す」を出します

Library タブの先頭にも、空・走査中・取消・未完了・権限の拒否・失効・読み取り失敗のどれに当たるかを `libraryNotice` で決めて出し、同じ操作（追加・取消・やり直し・選び直し）を置きます。

## 実装提案（仕様に値がない点）

- 窓の大きさ 100 行、窓の動かし方（25 行単位）、行の最小の高さ 56 dp、アート 48 dp
- 初期の並びは曲名の昇順。アルバムを開いたときだけディスク・曲番号の順
- 型と関数の名前（`LibraryBrowser`、`LibrarySelection`、`TrackSelection`、`LibraryNotice`、`LibraryGrouping`、`LibraryGroupQuery`、`LibraryFolder`、`LibraryField.TRACK_NUMBER`、`NavigationPage.SOURCE`）と `library-` で始まる entry ID
- 受付後に Now Playing を開く。受付前の失敗は Library に残す
- フォルダ名にプロバイダーの文書 ID をそのまま使う。表示名は走査で保存していない
- 一覧に件数は出さない（design.md §3.2.1）。グループの曲数はデータとしてだけ持つ
- ジャンル・年の一覧は作っていない。曲の絞込みの引数としては既に使える

## 制約と未実施

- アーティストの一覧は表示用のアーティスト名でまとめます。曲の絞込みはクレジットの名前にも一致するので、開いた一覧の曲が増えることがあります
- 大文字小文字の区別は SQLite の `NOCASE`・`lower()` と同じく ASCII だけです
- 回転では ViewModel が状態を保ちます。プロセスの終了後は表示・検索語・最後の走査の結果を復元しません
- 受付後にサービスが何も報告しないと「準備中」のままになります。別の曲を選べば置き換わります
- 実機（Galaxy S25・FiiO M21・S20）、TalkBack の読み上げ、実在のライブラリでの速度とメモリの測定、実際のアート画像を持つ音源での一覧は未実施です
