# キューの保存と更新

[#38](https://github.com/4rtofl/Audipp/issues/38) は FR-PLY-04 のキュー保存と DD-DB-02・DD-QUEUE-01 の更新契約を扱う。既存の `LibraryDatabase` を v2 に上げ、v1 のライブラリ行をそのまま移行する。

- `QueueDao.replaceEntries` に期待 revision と、編集後の全項目を再生順で渡す。同じ版を重複追加する場合は、項目ごとに別の `QueueEntryId` を割り当てる。音源が消失しても、既存の Variant を参照する項目は保存できる。
- 再生側は現在項目を削除する前に、再生遷移を取り消して停止を要求する。DAO が `StopRequired` を返した場合も、同じ revision と停止要求済みの項目 ID で再試行する。再生側は実際の現在項目も確認し、再試行を再生コマンドと直列化する。
- 順序・revision・チェックポイントは同じトランザクションで更新される。順序だけを変えた場合は現在項目と位置を保持する。現在項目を削除した場合は両方をクリアする。旧 revision のチェックポイント保存は拒否する。

| 試験 | 確認範囲 |
| --- | --- |
| TEST-PLY-01 | 隣接交換、逆順、追加と削除の混在、途中失敗時のロールバック、重複・消失参照の保持 |
| TEST-RESTORE-01 | 順序変更時の項目・位置保持、停止要求とクリアの順序、削除後の旧チェックポイント拒否 |
| v1 → v2 | 旧スキーマで作成したライブラリ行の保持と、新しいキューの作成 |

上記を API 35 の Robolectric で検証し、`QueueDaoTest` の4件が成功した。実 Service とキューの接続は #83、定期チェックポイント・プロセス終了後の復元は #62 で扱う。
